# UI 证据台账（每轮 UI 改动的真机数字）

> 用途：S/P 阶段每轮都要有"截图 + 像素/几何数字"。这里按轮次记，避免证据散在对话里。
> 截图统一放 `docs/device/vNN/`。设备：TicWatch Pro 5，466×466，density 2.0（1dp = 2px）。

## 0.0.0.143 · 根因找到：改 settingsStyle 后设置页**不会自己重绘**

同一次会话里依次 POST `TERMINAL → BALLOON → NEON → ARC`（每次间隔 2s，POST 全 200，`/api/state` 也显示已切到 ARC），
每次截图的 sha256 前 12 位：

| 切到 | 截图哈希 | 字节 |
|---|---|---|
| TERMINAL | 8B731F4A474D | 16839 |
| BALLOON | 8B731F4A474D | 16839 |
| NEON | 8B731F4A474D | 16839 |
| ARC | 7283FC24EDF8 | 31820 |

前三张**完全一样**，说明画面还停在终端档 —— 也就是：**改设置项不会让设置页重绘**，
必须离开并重新进入该页才会生效。这也解释了 0.0.0.141/142 两次批量截图"十套只有 3 帧"。

**这条本身是个产品问题**：控制台改风格后，手表上正打开着的设置页应该跟着变；
现在要退出去重进。要么在拿到新设置时触发重组，要么明确"改完需重进"（后者体验差）。

下一轮取证脚本必须改成：POST → **退到主页 → 重新进设置页** → 截图。

## 0.0.0.142 · 十套批量截图仍无效（3 个哈希 / 10 套）——工具留下，结论是别再用这条路

新增 `docs/tools/style-shots.mjs`：切风格 → 唤醒 → **dump 前先删旧 XML**（防止拿上一轮残留骗自己）→
校验确实是设置页 → 截图 → 用 **sha256 前 12 位**判断是否与上一套同一帧。

实跑结果（10 套只有 3 个不同哈希）：

| 风格 | 字节 | 哈希 | 判定 |
|---|---|---|---|
| BALLOON | 17364 | 2d7b2c40849e | 有效 |
| SQUARE | 17364 | 2d7b2c40849e | **与上一套同一帧** |
| GOOGLE_CARD | 17281 | 825838ad32a7 | 有效 |
| TERMINAL / M3_LIST / M3_TRANSFORM / NEON | 17281 | 825838ad32a7 | **同一帧** |
| PAPER | 17108 | d7cf5854a29e | 有效 |
| GLASS / ARC | 17108 | d7cf5854a29e | **同一帧** |

**结论**：`exec-out screencap -p` 在这台表上、这种"刚切完风格"的时机返回的不是当前画面
（dump 说在设置页，截图却是另一帧；很可能是息屏/表盘帧或上一帧）。

**所以 S7 的十套取证不走批量脚本**，改用已被验证有效的 `release-check` 一条路：
它每次运行都会"唤醒 → 阻尼上滑 → dump 校验 → 截图"，一次拍一套，跑十次（约 50 分钟）换取十张真图。
批量脚本保留但**不再作为证据来源**。

## 0.0.0.141 · S7 十套批量截图**失败**（十张同尺寸 = 同一帧，已删除）

做法：循环把 `settingsStyle` 依次设为十套，每次 `keyevent 224` 唤醒后 `screencap`。
结果：十张 PNG **全部 17280 字节**（同一帧），显然不是十套界面 —— 采集无效，**已全部删除**，不留假证据。

进一步验证：`svc power stayon true` + 唤醒 + 点一下再截图，仍是 17280 字节 → 说明capture 拿到的不是设置页，
而是息屏/表盘那种整屏一致的画面（十套风格自然一模一样）。

**结论**：批量截图不能"切风格 → 唤醒 → 直接截"。`release-check` 之所以能截到，是因为它在截图前刚刚
做了"阻尼上滑 + dump 校验设置页文本"这套动作。

下一轮正确做法（写死）：
1. 每套风格都走 release-check 的同一套前缀动作（唤醒 → 短距阻尼上滑 → dump 里出现「模型与服务/全部启用」才继续）；
2. 截图后立刻校验"与上一套的字节数/像素哈希不同"，相同就判为无效并重试；
3. 十张都通过后，再写成 S7 回归表。

## 0.0.0.140 · release-check「进入设置页」偶发失败的根因（已修）

现象：连续几次跑到 **7/8**，失败项固定是「进入设置页」，而子页截图反而成功。

排查过程：
1. 先怀疑"装完等得不够" → 把固定 `sleep 5s` 改成轮询"界面是否就绪"：**仍然失败**（`界面就绪：是` 之后照样 FAIL）。
2. 再怀疑手势参数 → 原脚本用长距离快滑 `420→40 / 260ms`；换成台账里记的短距阻尼上滑 `380→180 / 500ms`：
   **8/8 通过**。

结论：新版聊天页上，**长距离快滑会触发列表滚动而不是设置入口**；短距阻尼上滑才命中。
脚本已改为「先短距上滑，后半段先 crown 滚到顶再上滑」，连跑验证 8/8。
