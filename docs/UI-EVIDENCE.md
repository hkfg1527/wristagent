## 0.0.0.124 · S3 起手：GOOGLE_CARD 现状量测（暴露真问题）

- 截图：`docs/device/v24/google-card-root.png`（`release-check` 第 2 段自己上机截的）
- 量法：逐行扫描最长连续像素段（阈值 RGB 和 > 90，避开卡片圆角处）

| 量 | 实测 | 结论 |
|---|---|---|
| 卡片最大宽度 | **352px = 176dp × 2.0** | ✅ 同宽约束成立 |
| 卡片最小宽度 | 260px | 圆角/视口裁切导致，不是宽度违规 |
| 卡间距（空白行） | **采样不到** | ❗ 见下 |

**发现（S3 必须改）**：截图里「配置导入导出」与「关于」**同在一张卡内** —— 也就是说 GOOGLE_CARD 的
`CARD_EACH` 并没有真的做到"一行一张独立卡"。用户要的"有些单独项做成小方块卡"更没有实现。
所以 S3 的实际任务是：把分组内的每一行拆成独立卡，并给开关类行做「小方块卡」粒度。

## 0.0.0.123 · S2 方角发丝线（缩进 + 半像素）



- 截图：`docs/device/v23/square-from-release-check.png`（SQUARE 档根页底部：无卡片、只有发丝线）
- 量法：逐行扫描 longest 连续非黑像素段（阈值 RGB 和 > 45）

| 量 | 实测 | 对应代码 |
|---|---|---|
| 发丝线宽度 | **296px**（=148dp），起点 x=85 | 卡宽 352px 两侧各缩进 **28px = 14dp**（`SettingsRowSidePadding`） |
| 发丝线高度 | **1 物理像素**（每条线只出现在一个 y：31 / 128 / 225） | `0.5.dp`（2.0 密度 → 1px） |
| 线间距（行高） | 128 − 31 = **97px**，225 − 128 = **97px** | 行距由 `RowVerticalPadding` + 文本高度决定 |

结论：方角档的"缩进 + 半像素"在真机上成立，且与文字左缘对齐（x=85 与文字左缘同列）。
