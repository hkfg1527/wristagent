## 0.0.0.141 · S7 十套批量截图**失败**（十张同尺寸 = 同一帧，已删除）

做法：循环把 `settingsStyle` 依次设为十套，每次 `keyevent 224` 唤醒后 `screencap`。
结果：十张 PNG **全部 17280 字节**（同一帧），显然不是十套界面 —— 采集无效，**已全部删除**，不留假证据。

进一步验证：`svc power stayon true` + 唤醒 + 点一下再截图，仍是 17280 字节 → 说明capture 拿到的不是设置页，

**结论**：批量截图不能"切风格 → 唤醒 → 直接截"。`release-check` 之所以能截到，是因为它在截图前刚刚
做了"阻尼上滑 + dump 校验设置页文本"这套动作。

下一轮正确做法（写死）：
1. 每套风格都走 release-check 的同一套前缀动作（唤醒 → 短距阻尼上滑 → dump 里出现「模型与服务/全部启用」才继续）；
2. 截图后立刻校验"与上一套的字节数/像素哈希不同"，相同就判为无效并重试；
3. 十张都通过后，再写成 S7 回归表。

## 0.0.0.140 · release-check「进入设置页」偶发失败的根因（已修）

现象：连续几次跑到 **7/8**，失败项固定是「进入设置页」，而子页截图反而成功。

排查过程：
1. 先怀疑"装完等得不够" → 把固定 `sleep 5s` 改成轮询"界面是否就绪"：**仍然失败**（`界面就绪：是` 之后照样 FAIL）。
2. 再怀疑手势参数 → 原脚本用长距离快滑 `420→40 / 260ms`；换成台账里记的短距阻尼上滑 `380→180 / 500ms`：
   **8/8 通过**。

结论：新版聊天页上，**长距离快滑会触发列表滚动而不是设置入口**；短距阻尼上滑才命中。
脚本已改为「先短距上滑，后半段先 crown 滚到顶再上滑」，连跑验证 8/8。

### 表冠按行滚动（0.0.0.199）

**实现**：`rotaryLinesToScroll(acc, delta, linePx)` 把连续像素量化成整行（余量恒 < 一行），
`onRotaryScrollEvent` 里按 `lines × linePx` 调 `state.scrollBy`；只接在 TERMINAL 上（其余四套不抢表冠，
有源码守卫 `onlyTerminalWiresTheRotary`）。单测 6 条：不足一行不滚、跨行取整、负向、余量不越界、行高为 0 抛错。

**真机取证（部分成功）**：
- 本机 `input` 命令**没有** `roll` 子命令（Android 13 的 input 只到 draganddrop），所以走 root 注入：
  `getevent -pl` 显示 `/dev/input/event0`（slate-spi）提供 **REL_WHEEL**；
  `sendevent /dev/input/event0 2 8 <n>; sendevent /dev/input/event0 0 0 0` 可注入。
- 注入 +1 格后整屏哈希从 `BE44B920C0` 变为 `C68A317662` —— **表冠事件确实被接到并产生了滚动**。

### 行网格定位到 36px（0.0.0.200）

### TERMINAL 的 Enter 与焦点（0.0.0.221）

三个真机才会暴露的点，都有日志/像素证据：

1. **Enter 必须在 Compose 层消费，且按下与抬起都要消费。**
   只吃 KeyDown 时 KeyUp 会漏给系统；本机系统把 Enter 抬起当"回桌面"，实测直接退出 App。
2. **Compose 只在节点持有焦点时才收得到键事件。**
   从后台切回后焦点会丢 -> Enter 漏给系统。修法：LocalWindowInfo.current.isWindowFocused
   变 true 时重新 requestFocus()。
3. **input keyevent 66 能到达 Compose**：日志 `composeKey type=KeyDown key=Key code: ... focused=tools`
   （focused 是焦点行 key）-> 焦点与粘性选择都生效。

**我自己踩的判据错误（第二次犯同类）**：判断"是否还在设置页"时用顶部标题 `连得上` 做标记 ——
但执行命令后列表会跟到底，`连得上` 已滚出视野、不在 dump 里，于是误判成"页面被关掉"。
**页面身份标记必须与滚动位置无关**：改用底栏 `[ 风格 ]` 或状态栏 `[n/4] NL`。改正后复测：
`# open` 出现、底栏与状态栏都在 -> Enter 行为正确，App 未退出。

### 长按翻整屏：从"发出的 delta"到"屏幕真的位移"（0.0.0.223）

| 操作 | 底栏读数 | 含义 |
|---|---|---|
| 顶部 | `[1/4] 12L` | 第 1 分区 |

### 失败尝试留档：TerminalStyle.kt 拆分（已整体回滚）

目标：把 686 行的 `TerminalStyle.kt` 按职责拆成 3 个文件（行渲染 / 底栏与滚动条 / 布局算术），用基线哈希证明零变化。

三次踩坑，最终**回滚**：
1. 新文件放进 `style/` -> 立刻被三条架构守卫拦下（"每个风格恰好一个文件"、"style 里禁止硬编码 sp"、"动效接线"）。
   这与 `TerminalStylePicker.kt` 的教训**完全相同**：`style/` 被守卫视为"风格渲染器目录"，非渲染器必须放外层；
2. PowerShell 做 Kotlin 结构性改写（按行号删块 + 插 import）连续出错：
   一次 `Resolve-Path` 对不存在的目标报错导致**目标文件没写成、源文件已被删**（靠 `git checkout` 救回）；
   一次插入 import 时把两行粘成 `TerminalTrackCellimport`，编译直接语法错误；
3. 每次都要重跑编译 + 守卫，成本远高于收益。

**结论**：这不是"拆分不重要"，而是**工具选错了**。正确做法：
- 先 `write` 建新文件（内容整体搬），再用 `edit` 从原文件删掉那一段（old/new 精确匹配，不按行号）；
- 每次只搬一块，搬完立刻 `compileDebugKotlin`，绿了再搬下一块；
- 新文件一律放 `settingsv2/` 根下，不放 `style/`。

回滚后复验：全量单测绿、`release-check` 8/8（0.0.0.233）、五套 `distinct 5/5`、
TERMINAL 哈希 `c408b5c355af`（= 基线），说明回滚干净。
