## 0.0.0.141 · S7 十套批量截图**失败**（十张同尺寸 = 同一帧，已删除）

做法：循环把 `settingsStyle` 依次设为十套，每次 `keyevent 224` 唤醒后 `screencap`。
结果：十张 PNG **全部 17280 字节**（同一帧），显然不是十套界面 —— 采集无效，**已全部删除**，不留假证据。

进一步验证：`svc power stayon true` + 唤醒 + 点一下再截图，仍是 17280 字节 → 说明capture 拿到的不是设置页，

**结论**：批量截图不能"切风格 → 唤醒 → 直接截"。`release-check` 之所以能截到，是因为它在截图前刚刚
做了"阻尼上滑 + dump 校验设置页文本"这套动作。

下一轮正确做法（写死）：
1. 每套风格都走 release-check 的同一套前缀动作（唤醒 → 短距阻尼上滑 → dump 里出现「模型与服务/全部启用」才继续）；
2. 截图后立刻校验"与上一套的字节数/像素哈希不同"，相同就判为无效并重试；
3. 十张都通过后，再写成 S7 回归表。

## 0.0.0.140 · release-check「进入设置页」偶发失败的根因（已修）

现象：连续几次跑到 **7/8**，失败项固定是「进入设置页」，而子页截图反而成功。

排查过程：
1. 先怀疑"装完等得不够" → 把固定 `sleep 5s` 改成轮询"界面是否就绪"：**仍然失败**（`界面就绪：是` 之后照样 FAIL）。
2. 再怀疑手势参数 → 原脚本用长距离快滑 `420→40 / 260ms`；换成台账里记的短距阻尼上滑 `380→180 / 500ms`：
   **8/8 通过**。

结论：新版聊天页上，**长距离快滑会触发列表滚动而不是设置入口**；短距阻尼上滑才命中。
脚本已改为「先短距上滑，后半段先 crown 滚到顶再上滑」，连跑验证 8/8。

### 磁滑吸附：量化证明 + 反证对照（0.0.0.194）

录屏在 Wear 上拿不到有效帧，`screencap` 单次 469~555ms 又长于任何滚动动画 —— 所以不"看动画"，
改为判决**离散性**：同一条复位路径（`force-stop → am start → 上滑进设置页`）之后做一次慢拖
（900ms，末速度≈0.04px/ms，不产生惯性），松手等 1.3s 到静止态，然后量两样东西：
整屏 SHA256、以及 `uiautomator` 里首区标题「连得上」的像素 bounds。

| 风格 | 拖动距离(px) | 哈希静止态 | 最大共用距离数 | 判据 |
|---|---|---|---|---|
| M3_CARD（`snapFlingBehavior`） | 12/24/36/48/60/72/84/96/160/240/320/400 | **3** | **7**（36~160 全部同哈希） | 态数≤4 且最大组≥3 → PASS |
| TERMINAL（无吸附，对照组） | 12/24/36/48/60/72/84/96 | **7** | 2（12/24 未过 slop，等于空拖） | 态数≥4 → PASS |

M3_CARD 的三个静止态分组：`{12,24}` / `{36,48,60,72,84,96,160}` / `{240,320,400}`。
「如果只是拖到底，大的距离必然同态」—— 实测第 2、3 组是两个不同态（第 3 组首卡已滚出视野），
所以离散性来自吸附而不是到底。

**交叉校验**：marker 在屏幕内的 9 次里，dump 坐标给出的划分与像素哈希给出的划分**完全一致**
（`12,24 | 36,48,60,72,84,96,160`）。

**两版写错的判据（留档）**：
1. R2 要求"静止态步长 == 行距 86px"，实测 25px。前提是"滚动=刚性平移"，而 `SurfaceTransformation`
   会把非锚点项朝中心**平移**（实测卡内行距 86px、文字高 47px 都不变 → 不是缩放），前提不成立。
2. R3 用"两仪器同一划分"直接判对照组，被判 FAIL —— 实际是 marker 顶到 y=0 后被屏幕裁切
   （h 从 32 掉到 26/15/3），属仪器上限而非缺陷。

工具：`docs/tools/snap-probe.mjs`（`exit 0` 打印 `SNAP_PROBE_OK`），原始截图与 `report.txt` 在
