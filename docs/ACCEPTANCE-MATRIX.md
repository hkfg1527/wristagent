# 输入验收矩阵（P1）

> 目标：把"这个页面跟不跟手"变成可重复的检查，而不是"我觉得有点怪"。
> 全部命令都在这台表上跑过（TicWatch Pro 5 / `C101X35122973`），不是纸面设计。

## 1. 两类输入怎么注入（已打通）

| 输入 | 做法 | 证据 |
|---|---|---|
| 触摸滑动 | `adb shell input swipe 233 340 233 150 300` | 一直可用 |
| **表冠旋转** | `adb shell su -c 'for i in $(seq 1 N); do sendevent /dev/input/event0 2 8 D; sendevent /dev/input/event0 0 0 0; done'` | 本次打通：**正 D = 列表往开头走（上），负 D = 往末尾走（下）** |

要点（踩过的坑）：

- 表冠节点是 `/dev/input/event0`（`slate-spi`，框架分类 `KEYBOARD | ROTARY_ENCODER`），轴是 **REL_WHEEL（2 8）**。
- shell 用户没有权限，必须 `su -c`；而且**整条命令要用单引号包住**再交给 `adb shell`，否则引号被吃掉，
  变成`su -c sendevent`（跑了个没参数的 sendevent）+ 后面以 shell 身份执行 → permission denied。
- 一格（D=1）走不动一屏，实用量级是 **D=5 × 20 次**≈ 一张卡的高度。
- 自带探针：`node docs/tools/input-probe.mjs <页面名>` —— 对当前屏幕先触摸上滑、再表冠回拨，
  比较前后可见文本签名，输出"响应 / 无变化"。

## 4. 判定口径

- **响应** = 可见文本签名发生变化且回到正确方向；**无变化** = 记缺陷。
- 每页都要同时验"触摸"和"表冠"两条；只验一条不算过。
- 每次改完 UI 至少重跑"设置根页 + 一个子页 + 对话页"三行。
