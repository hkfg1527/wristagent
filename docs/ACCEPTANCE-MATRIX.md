## 1. 两类输入怎么注入（已打通）

| 输入 | 做法 | 证据 |
|---|---|---|
| 触摸滑动 | `adb shell input swipe 233 340 233 150 300` | 一直可用 |
| **表冠旋转** | `adb shell su -c 'for i in $(seq 1 N); do sendevent /dev/input/event0 2 8 D; sendevent /dev/input/event0 0 0 0; done'` | 本次打通：**正 D = 列表往开头走（上），负 D = 往末尾走（下）** |

要点（踩过的坑）：

- 表冠节点是 `/dev/input/event0`（`slate-spi`，框架分类 `KEYBOARD | ROTARY_ENCODER`），轴是 **REL_WHEEL（2 8）**。
- shell 用户没有权限，必须 `su -c`；而且**整条命令要用单引号包住**再交给 `adb shell`，否则引号被吃掉，
  变成`su -c sendevent`（跑了个没参数的 sendevent）+ 后面以 shell 身份执行 → permission denied。
- 一格（D=1）走不动一屏，实用量级是 **D=5 × 20 次**≈ 一张卡的高度。
- 自带探针：`node docs/tools/input-probe.mjs <页面名>` —— 对当前屏幕先触摸上滑、再表冠回拨，
  比较前后可见文本签名，输出"响应 / 无变化"。

## 2.8 网页控制台 · 接口与写入链（2026-11-18 实测，0.0.0.85）

做法：`adb forward tcp:18080 tcp:8080`，令牌取手表端 `console_prefs.xml` 的 `console_token`。

| 端点 | 无令牌 | 带令牌 | 期望 | 结论 |
|---|---|---|---|---|
| `/healthz` | 200 | 200 | 公开存活探针 | ✅ |
| `/api/ping` | **401** | 200 | 鉴权生效 | ✅ |
| `/api/state` | **401** | 200 | 返回完整设置快照（40+ 字段） | ✅ |
| `/api/settings`（GET） | 401 | **405** | 写接口不该接受 GET | ✅ 符合设计 |

**写入链端到端**：

```
POST /api/settings  {"temperature":0.7}  → 200，响应体里 temperature=0.7
GET  /api/state                          → temperature=0.7
POST /api/settings  {"temperature":0.8}  → 200，state 回到 0.8
```

即"网页写入 → 手表偏好 → 再读回"这条链是通的，且**鉴权在写接口上真的生效**（无令牌 401）。

**仍未覆盖**：页面本身的交互（标签切换、表单校验、三档皮肤下的可点性）。
那部分需要真浏览器驱动，工具链在 `docs/tools/console-shot.mjs`（headless Edge + CDP），下轮做。

## 2.9 网页控制台 · 页面级交互（2026-11-18，0.0.0.87）

脚本 `docs/tools/console-e2e.mjs`：headless Edge + CDP 驱动真页面，**断 DOM 与抓到的请求**，不是看截图。
前置 `adb forward tcp:18080 tcp:8080`，`CONSOLE_TOKEN` 取手表端 `console_token`。

| 组 | 覆盖 | 判据 |
|---|---|---|
| A | 认证闸门 | 无令牌顶栏「令牌 缺失/无效」且真的收到 401；带令牌「令牌 有效」；设备名/后端/端口/状态灯 |
| B | 令牌弹层 | 点顶栏「令牌」开弹层、令牌已填、取消收起 |
| C | 十个页面 | 逐个点侧栏：`content[data-page]` 对上、`.page-title` 等于行名、`document.title` 同步、`.row` 数 > 0、高亮跟随 |
| D | 搜索 | 开层、搜「温度」命中、点结果跳到「生成参数」并给该行加 `is-flash`、无命中出空态、Esc 关闭 |
| E | 非法 JSON | `customHeaders` 输入 `{` → 页内「不合法」+ `tone=bad` + **记录到的 POST 数为 0**；合法 JSON 回「已记录 1 个请求头」，但它是本地草稿键，仍 **0 笔请求**，出「只保存在本地」横幅 |
| F | 文本域写回 | `customSystemPrompt` 发一笔带该键的 POST、200、**中文原样往返**（无 U+FFFD）、出「已保存」、还原 |
| G | 滑杆写回 | 温度滑杆改数字胶囊 → 一笔带 `temperature` 的 POST → 手表侧读回同值 → 还原 |
| H | 三档皮肤 | 400px→watch、700px→phone、1280px→desktop；无横向溢出；≤900px 用顶部标签条不显示侧栏，>900px 反之 |
| I | 零 JS 异常 | 认证闸门刻意制造的 401 之外，页面不得有 console.error / exception / 4xx 资源错误 |

**这里查出的真缺陷（已修）**：`Content-Type: application/json` 不带 charset 时，NanoHTTPD 按 US-ASCII 解 body，
**网页里输入的中文会被逐字节换成 U+FFFD 再落库，且不可逆**（写「中文探针-ABC」读回来是 12 个 `�`）。
修法：`ConsoleCharset.withUtf8()` 在 `parseBody` 前把缺省 charset 补成 utf-8 并即时还原请求头，
网页端同时显式声明 `charset=utf-8`；单测 `ConsoleCharsetTest`（5 条）钉规则，本脚本 F3 钉端到端往返。

**同一轮修的第二个缺陷**：`/api/state` 的 `capabilities` 里没有设备名字段，网页顶栏只能显示「当前设备」。
现在 `ConsoleBridge` 把 `Build.MODEL` 带进能力表，顶栏实测显示 `TicWatch Pro 5`。

**同一轮修的第三个缺陷（真机实测出来的）**：保存会偶发 9 秒超时报「未保存」，而其实写已经落盘。
根因不在业务，在连接管理：NanoHTTPD 把**一条 TCP 连接**当成一个 worker 占着，而浏览器会保留空闲 keep-alive 连接；
服务端读超时关连接、客户端还没收到 FIN 的那一瞬间发出的请求会石沉大海（POST 不重试）。
实测数据：12 笔并发 POST 被拉成 5.3s / 10.3s / 15.4s / 20.4s / 25.4s（每笔正好卡在 5s 读超时上），
紧接着的一笔串行 GET 也要 5.06s。修法两条：`MAX_WORKERS` 8 → 32、空闲读超时 5s → 2s、
响应一律 `closeConnection(true)`（一问一答就关连接，局域网多一次握手，换掉整个竞态）。
修后同一压测：12 笔并发全部 ≤166ms，串行 GET 39~45ms；端到端 E2E 从 62/69 变 **69/69**。

**已接进发布自检**（0.0.0.88）：`node docs/tools/release-check.mjs` 的第 4 项就是这个脚本。
令牌不手填 —— 设备已 root，脚本 `su -c cat /data/data/dev.ghr.wristagent/shared_prefs/console_prefs.xml` 自己取。
