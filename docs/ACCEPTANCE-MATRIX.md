# 输入验收矩阵（P1）

> 目标：把"这个页面跟不跟手"变成可重复的检查，而不是"我觉得有点怪"。
> 全部命令都在这台表上跑过（TicWatch Pro 5 / `C101X35122973`），不是纸面设计。

## 1. 两类输入怎么注入（已打通）

| 输入 | 做法 | 证据 |
|---|---|---|
| 触摸滑动 | `adb shell input swipe 233 340 233 150 300` | 一直可用 |
| **表冠旋转** | `adb shell su -c 'for i in $(seq 1 N); do sendevent /dev/input/event0 2 8 D; sendevent /dev/input/event0 0 0 0; done'` | 本次打通：**正 D = 列表往开头走（上），负 D = 往末尾走（下）** |

要点（踩过的坑）：

- 表冠节点是 `/dev/input/event0`（`slate-spi`，框架分类 `KEYBOARD | ROTARY_ENCODER`），轴是 **REL_WHEEL（2 8）**。
- shell 用户没有权限，必须 `su -c`；而且**整条命令要用单引号包住**再交给 `adb shell`，否则引号被吃掉，
  变成`su -c sendevent`（跑了个没参数的 sendevent）+ 后面以 shell 身份执行 → permission denied。
- 一格（D=1）走不动一屏，实用量级是 **D=5 × 20 次**≈ 一张卡的高度。
- 自带探针：`node docs/tools/input-probe.mjs <页面名>` —— 对当前屏幕先触摸上滑、再表冠回拨，
  比较前后可见文本签名，输出"响应 / 无变化"。

## 2.5 表冠 × 页面：逐页实测表（2026-11-15 06:35 全量重跑）

判据：注入表冠后 dump 可见文本签名，**签名变了 = 响应**；到顶后继续向上**必须不动**（无橡皮筋回弹也算硬约束：禁止形变）。

| # | 页面 | 顶部继续向上 | 向下滚 | 向上滚回顶 | 回顶后签名 == 起始签名 | 进程存活 |
|---|---|---|---|---|---|---|
| 1 | 设置根页（自带 handler） | **不动** ✅ | 响应 ✅ | 响应 ✅ | **是** ✅ | ✅ |
| 2 | 设置子页（`SettingsSubPage` 共用 handler，代表页=网络与请求） | **不动** ✅ | 响应 ✅ | 响应 ✅ | **是** ✅ | ✅ |
| 3 | 聊天页（`ChatScreen` + 库自带 `rotaryScrollable`） | 已在新消息底部 → **不动** ✅ | 到底后向下 **不动** ✅ | 响应 ✅（回看历史） | — | ✅ |

**结构性结论**：其余 16 个子页全部走 `SettingsSubPage`，与第 2 行**同一条代码路径**，
所以表冠行为一致；这 3 行覆盖了全站**仅有的三条**不同的滚动实现（根页 handler / 子页共用 handler / 聊天页库组件）。

**已知未覆盖**：
- 触摸拖拽与磁滑（`RotaryScrollEvent` 之外的路径）未逐页测。
- 子页内层页（如网页控制台里的体检页）只抽样过 1 个。
- 底栏自动收起在真实对话中的时序（需要一轮完整的流式回复）。

## 3.5 自动化导航的坑（血泪）

1. **同名节点有两处**：根页的 hero 卡标签和分区导航行都叫「工具与 MCP」/「语音与唤醒」。
   点第一个会点到不可点的 hero 卡上（毫无反应）。判据：**先滚到能看到分区标题**（如「语音与工具」），
   再点它下方那一行；导航行的右边一定有取值（如「全部启用」）。
2. **焦点/列表位置会被表冠改变**，所以每次 tap 前必须重新 dump 拿坐标，不能复用上一轮的坐标。
3. 子页返回用底部的「完成返回」行（在列表**最末尾**），不是系统返回键 —— 系统返回键会直接退到聊天页。

## 4. 判定口径

- **响应** = 可见文本签名发生变化且回到正确方向；**无变化** = 记缺陷。
- 每页都要同时验"触摸"和"表冠"两条；只验一条不算过。
- 每次改完 UI 至少重跑"设置根页 + 一个子页 + 对话页"三行。
