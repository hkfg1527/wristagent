## 零、 项目核心宗旨与开源免死宣言

1. **绝对禁止任何形式的造假**：没有实现的功能就诚实报错或禁用，坚决杜绝用硬编码假文案骗取大模型和用户信任。
2. **拒绝平庸丑陋的穿戴 UI**：Wear OS 不是小号平板，必须彻底针对圆形视口进行曲率贴合排版、真实物理微晶质感与液态阻尼动效。
3. **彻底铲除上帝组件**：全面拥抱 UDF（单向数据流）与单一状态机（State Machine），消灭状态冲突与静态内存泄漏。

## 一、 核心重塑需求清单（必须彻底执行的技术指标）

### 需求 1：通信与核心引擎真实化（消灭假流式与假工具）
- **真·SSE 流式客户端接入**：
  - 彻底删除 `AgentDispatcher.kt` 中 `delay(12)` 切割全量 JSON 的人造假打字机。
  - 使用标准的流式协议（如 OkHttp `EventSource` 或基于 `ResponseBody.byteStream()` 的逐行缓冲读取），真实解析服务端的 `data: {...}` 事件，实现毫秒级首字上屏（TTFT）。
- **工具集真实性回归**：
  - `web_search`：删除所有写死的百科套话。若穿戴端未配置真实搜索端点或手机中继，必须明确返回错误 `ToolResult(success = false, output = "未配置公网检索服务，请通过手机端或配对页配置 API")`。
  - `query_time_weather`：剔除硬编码的 `"22℃ 晴朗微风"`。无天气 API 时，明确说明仅获取本地系统时间。
  - `SecurityGuardrail`：将此前只在单元测试里跑过、实际运行中从未调用的 `assessCommand` 真正接入执行链路，或者精简合并，严禁写摆设代码。

### 需求 2：架构彻底解耦（UDF 与单一状态机）
- **引入 `MainViewModel`**：
  - 将 `MainActivity.kt` 散落在 700 行 Composable 里的 `sessions`、`activeSessionId`、`bottomBlockMode`、`agentState`、`isRecordingVoice` 等全部收拢进 ViewModel。
  - 界面只订阅 ViewModel 的 `StateFlow`，实现配置变更（横竖屏/重建）状态不丢。
- **状态机去冲突（消除神仙打架）**：
  - 定义严格的状态转移枚举：`IDLE` -> `LISTENING` -> `THINKING` -> `STREAMING` -> `ACTION_APPROVAL` -> `FINISHED`。
  - 严禁后台协程在状态已经流转到 `FINISHED` 后，又通过延迟任务把底栏强行改回 `THINKING_STOP`；消除审批挂起时 `CancellableContinuation` 悬空导致的滑块死锁。
- **彻底铲除静态伴生泄漏**：
  - 废除 `MainActivity.companion` 上的 `onBackPressedCustom` 和 `onPromptTrigger` 静态变量，改用标准的系统返回调度器（`BackHandler`）与事件通道（`SharedFlow` / Channel）。

### 需求 3：视觉排版与物理动效彻底重做（拉满质感，消灭癫痫动画）
- **圆形视口自适应排版**：
  - 彻底重构正方形大卡片被圆表盘生硬切角的问题。列表正文采用动态水平内边距（Padding）或曲率缩进，卡片边缘随表盘上下滑动呈现平滑过渡，消灭生硬的钝刀切菜式遮罩。
- **消灭整块文字抽搐（SpringStreamingText 重构）**：
  - 坚决杜绝“每吐一个字就把几百字文本放大 1.025f”的智障震颤动效！
  - 改用每个新增字符的优雅透明度渐现（Alpha In）与底栏平滑微弹，文字主体保持绝对稳定，阅读不晕眩。
- **液态玻璃手势底栏（BottomInteractiveBlock）重塑**：
  - 优化手势分流，手势判定（单击、长按、滑动）必须使用明确的时间与位移门限状态机，杜绝误触。
  - 两翼副键展开增加粘滞回弹动效与平滑过渡，消灭干瘪生硬的位移。
- **旋转表冠（Rotary）真实惯性联动**：
  - 修复 `OnboardingScreen` 中直接返回 `true` 的空转伪事件。
  - 为整个列表滚动接入真正的物理惯性衰减（Fling Decay）与刻度磁吸震动反馈。
- **杜绝多层点阵重复渲染**：
  - 移除单个会话卡片内部重复实例化的 `UnifiedMatrixCanvas`，让全局点阵底纹统一样式渲染，消除 GPU 无意义的重绘损耗。

### 需求 4：超大文件拆解与工程规范化
- **拆分 `SettingsScreen.kt`（1408 行）**：
  - 在 `presentation/ui/settings/` 目录下拆解为独立的 7 个 Sub-sheet 组件，主文件仅保留顶层列表与路由状态。
  - 修复超参数调节面板（Temperature）在手表上的反人类超小微距按钮，适配表冠滚轮微调。
- **拆分 `MainActivity.kt`（1190 行）**：
  - 抽离 `TopClockBar.kt`（顶部弧形时钟）。
  - 抽离 `VoiceListeningOverlay.kt`（语音识别全屏动效）。
  - 主仪表盘精简为纯声明式 UI 容器。
