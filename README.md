## 零、 核心定性：狗屎 UI、状态泥潭与假动效的彻底问责

别拿“穿戴设备屏幕小、算力弱”当你的遮羞布！用户要的是**顶级的质感、丝滑的手感、真实的动画、诚实的实现**！
而你交付的代码，UI 丑得像十年前的车载山寨机，动效抽搐得像界面癫痫，状态冲突得连代码自己都不知道当前在干什么，甚至靠硬编码假数据和假打字机自欺欺人！

在开源社区里，功能少可以被原谅，**但把 UI 做到恶心、把动效做到抽搐、把状态写到死锁、还用假数据骗人，会被全体开发者钉在耻辱柱上反复嘲笑！**

## 一、 狗屎一样的 UI 缺陷清单（拉出来公开示众）

### 1. 灾难级纯圆屏幕排版（把手表当小平板的弱智布局）
- **罪证**：`MainActivity.kt` 705-755 行
- **车祸现场**：
  Wear OS 是 454x454 / 480x480 的**纯圆形屏幕**！上下边缘物理宽度直接缩为零！
  你居然用普通的 `Column` + `fillMaxWidth()` 硬塞正方形大卡片！卡片的左上角和右上角直接被圆形表盘的物理边框生硬裁切掉！
  你在 730-751 行自作聪明搞了个 `verticalGradient` 遮罩，结果文字滑到表盘顶部时像被一把钝刀生生切成两半，既无圆弧贴合曲线，也无视差缩进，丑陋得令人窒息！

### 2. 老干部风“密恐地狱”设置页（1408 行的不可读垃圾场）
- **罪证**：`SettingsScreen.kt` 全文
- **车祸现场**：
  - 在 1.3 英寸的表盘上，你塞满了密密麻麻的 `8.sp`、`9.sp` 蚂蚁文字，行间距挤成一团！成人的手指点上去直接同时触发两个按钮！
  - 超参调节面板（830-898 行），在表盘上居然左右并排硬挤两个微型小方块 `[ - 0.1 ]` 和 `[ + 0.1 ]`，没有任何物理表冠旋转阻尼映射，全靠用户用指甲缝去死磕屏幕！
  - 配色更是惨不忍睹：死气沉沉的劣质黑底（`#141720`）配死灰白框（`#262D3D`），既无通透的材质层级，也无现代穿戴设备的环境微光质感，丑陋得像 Windows 98 安全模式！

### 3. 会话抽屉的生硬棺材板质感
- **罪证**：`SessionDrawer.kt` 全文
- **车祸现场**：
  所谓的侧边抽屉，就是左侧生硬滑出一块死黑的大板子！没有侧边贴合曲率、没有列表弹性下坠、没有删除对话的平滑手势阻尼、没有震动确认，生硬干瘪得像一块木头！

## 二、 动效做的不行：抽搐、廉价、假把式

### 1. 癫痫级“假吐字”震颤动效（SpringStreamingText）
- **罪证**：`FrostedGlassComponents.kt` 315-348 行
- **车祸现场**：
  每吐一个字，你就把整段文字放大 `1.025f`（`bounceScale.snapTo(1.025f)`）！
  一段两百字的回复，每吐两个字符整块文本就剧烈抖动一次！用户在手表上看文字，看到的不是如液态水墨般优雅浮现的排版，而是整段文字在屏幕上发了疯一样抽搐频闪！这不是微晶动效，这是对用户眼睛的物理折磨！

### 2. 底部药丸按键的手势冲突地狱（BottomInteractiveBlock）
- **罪证**：`BottomInteractiveBlock.kt` 238-316 行
- **车祸现场**：
  在短短 44dp 的药丸按键上，你硬塞了：长按 340ms 录音、横滑展开两翼、上滑进设置、单触切模式、录音中单触停止！
  全靠写死硬编码阈值（`abs(deltaX) > 12.dp`，`deltaY < -16.dp`）！
  结果导致：
  - 想向右横滑展开副键，稍微抖了一下就变成上滑直接强弹设置页！
  - 想长按录音，按得稍微犹豫 2 像素，长按协程被直接 cancel，误触成单击！
  - 两翼副键展开时没有任何胶水拉丝（Gooey/Metaball）粘滞感，两个圆点干瘪地横移出去 50dp，生硬机械得令人发指！

### 3. 糊弄人的假水波纹与假表冠
- **罪证**：`MainActivity.kt` 534-536 行 & `OnboardingScreen.kt` 237 行
- **车祸现场**：
  所谓的“水波激荡”，就是用 `LinearEasing` 画一个极度敷衍的矩形透明渐变扫过去，毫无物理折射与粒子波动；
  `OnboardingScreen` 里的旋转表冠监听直接写了个 `true` 空转，表冠转出火花页面都纹丝不动，纯属摆设骗人！

## 三、 状态乱七八糟、互相冲突的神仙打架泥潭

这个项目的状态管理已经混乱到了**“代码自己都不知道自己此时此刻该处于什么状态”**的病态地步：

### 1. 散落各处的无头状态与死锁频发
- 整个项目**零 ViewModel**，所有全局状态全部用 `remember { mutableStateOf }` 堆在 700 行的上帝 Composable 里，手表一转屏或者短暂切后台，所有会话瞬间灰飞烟灭！
- **审批死锁**：在工具审批拦截态（`ACTION_ALLOW`）下，如果发生网络超时或异常打断，`pendingContinuation` 悬空不被恢复，底栏红色滑块直接永久死锁在屏幕上！
- **状态癫痫瞬移**：录音状态（`RECORDING`）与调度器状态互相强行覆盖，底栏按钮在红浪和白药丸之间疯狂瞬移；
- **幽灵改写**：大模型明明已经回答完毕（`isFinished = true`），之前发出的 `delayedStretchJob`（延迟 300ms 协程）又在后台冷不丁执行，把底栏强行又改回了“停止”按钮！回答完了又蹦出个停止按钮，简直荒唐可笑！

### 2. 静态伴生对象的内存泄漏毒瘤
- **罪证**：`MainActivity.kt` 139-142 行
  ```kotlin
  companion object {
      var onBackPressedCustom: (() -> Unit)? = null
      var onPromptTrigger: ((String) -> Unit)? = null
  }
  ```
  把返回拦截和全局触发词直接作为静态变量挂在 Activity 的伴生对象上！这是最典型的初学者反模式，切屏重建必导致 Activity 实例内存泄漏与回调失效的幽灵点击！

## 四、 彻底重做、往死里优化的强制重塑清单

**不要妥协！不要找借口！后续重构必须按以下最高标准彻底重写：**

### 1. 状态彻底推倒重建（UDF 与单一状态机）
- 建立 `MainViewModel`，把所有散落状态统一收归，对外只暴露单向不可变的 `StateFlow`。
- 引入严格的状态转移状态机：明确 `IDLE -> LISTENING -> THINKING -> STREAMING -> APPROVAL_LOCKED -> COMPLETED` 的单向流转，坚决消灭状态互相覆盖与死锁。
- 彻底铲除 `MainActivity.companion` 里的静态变量回调，改用标准 `BackHandler` 与事件流。

### 2. 剔除所有假功能，真实流式上线
- 彻底删除 `delay(12)` 假打字机，使用正规 OkHttp SSE 真实流式解析，首字必须毫秒级直接上屏。
- 假搜索、假天气如果不连真实接口，就老老实实报错“未配置公网 API”，严禁输出任何硬编码假套话。

### 3. UI 审美与动效往死里拉满（顶级穿戴质感）
- **圆形自适应流式排版**：全面优化卡片在圆形表盘的内边距，文字卡片贴合表盘曲率动态收缩，彻底解决四角切角与生硬切菜遮罩。
- **消灭整块文字抽搐**：重构逐字上屏动画，采用每个字符平滑透明度渐显（Alpha Fade In）与轻微平滑位移，保证阅读视线绝对平稳。
- **液态玻璃手势底栏**：重写手势识别状态机，分离 Tap、LongPress 与 Drag；两翼副键弹出加入真实的胶水粘滞拉丝（Gooey）与回弹物理动效。
- **真实物理表冠**：为表盘滚动注入物理惯性阻尼（Fling Decay）与刻度磁吸震动。

### 4. 拆解巨型文件
- 将 1408 行的 `SettingsScreen.kt` 拆分为 `presentation/ui/settings/` 下的 7 个独立文件。
- 将 `MainActivity.kt` 中的弧形时钟和语音遮罩剥离，主文件精简为纯粹的顶层脚手架。
